= Use the Projects dashboard in Workload Factory for EDA
:icons: font
:imagesdir: ./media/

[.lead]
Use the Projects dashboard to track storage use across your FSx for ONTAP file systems and volumes. Filter the data by project, team, or application. View both overall and per-volume performance to help plan capacity and use resources more efficiently.

== Before you begin

You should have link:task-configure-project-dashboard.html[configured custom filters] for the Projects dashboard. If you haven't configured custom filters, you can still use the default filters (file system, volume type, and time range).

== Filter the dashboard

Filtering lets you focus on specific groups of storage resources. This makes it easier to spot trends, find problems, and create reports for stakeholders. By using multiple filters together, you can answer targeted questions such as: “How much storage is the ASIC project team using?” or “Which volumes in the US-West region have the highest IOPS?”

.About this task

You can filter the information displayed on the dashboard using a combination of default filters and any custom filters you configured.

.Steps

. Log in using one of the link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html[console experiences^].
. Select the menu image:workloads-menu-icon.png[The hamburger menu icon] and then select *EDA*.
. Select *Project*.
. Select the filters you want to apply from the available options:
* Default filters (file system, volume type, time range)
* Any custom filters you configured
. Select the refresh icon to update the dashboard information based on your filter selections.
. For an explanation of the information shown on a card, select the information icon for that card.

== View volume details

Looking at both total volume performance and individual volumes helps you plan capacity and improve performance. The Total view shows overall trends. The Volume view helps you find specific volumes that may need attention, tuning, or more resources.

=== View aggregated volume metrics

The Total view shows combined metrics for all volumes that match your filters.

.Steps

. Open the **Project** tab and make sure the **Total** tab is selected. This is the default view.
. Review the metrics displayed:
* Combined capacity across all volumes
* Aggregated IOPS
* Aggregated throughput
. Use this view to see trends and plan how much capacity you'll need in the future.

=== View individual volume performance

The Volume view shows how each volume performs over time. It highlights the top 10 volumes for each metric.

.Steps

. In the **Project** tab, select the **Volume** tab.
. Review the volume metrics:
* *Volume used capacity*: Shows volumes with the highest current used capacity
* *IOPS*: Shows volumes with the highest average IOPS during the selected time period
* *Throughput*: Shows volumes with the highest average throughput during the selected time period
+
NOTE: If you have more than 10 volumes, the rest will not appear in the detailed view.

. Hover over any volume line in the graphs to view detailed information:
* *Volume used capacity*: Volume name, used capacity at that point in time, and allocated capacity
* *IOPS*: Volume name, average IOPS for the time range, and maximum IOPS for the time range
* *Throughput*: Volume name, average throughput for the time range, and maximum throughput for the time range
. Use the legend to identify each volume. The same volumes use the same colors across all metrics so you can track them easily.

.Result

Use this data to:

• Analyze usage patterns  
• Spot possible bottlenecks  
• Find volumes that might need to be resized  
• See which projects or workloads use the most resources

== Best practices

Consider these recommendations when using the Projects dashboard:

* Check the dashboard regularly to spot patterns before they turn into problems.

* Use several filters at the same time to answer specific questions about how resources are being used.

* Look at both views: use Total to plan capacity and Volume to find and fix issues.

* Change the time range to see whether changes are normal or part of a growing trend.

* Record normal performance levels so it's easier to spot unusual behavior later.

* Use what you learn from the data to adjust resources, resize volumes, or improve performance before workloads are affected.
